# Поурочные материалы СПО

Проект для подготовки поурочных материалов: технологические карты (.docx),
презентации (.pptx) и практические задания (.docx), плюс локальный сайт
для работы с ними.

Сейчас в проекте одна дисциплина — **МДК.04.02 «Оценка эффективности
и контроль логистических систем»** (специальность 38.02.03, группа
ДЛ 301-2024, 84 ч, 43 занятия). Структура рассчитана на добавление
других дисциплин без переписывания кода: см. раздел
«Добавить новую дисциплину».

## Установка

```bash
pip install -r requirements.txt
python scripts/make_templates.py     # один раз: создаёт базовые шаблоны
```

## Команды

```bash
python scripts/build.py --lesson 5             # собрать комплект занятия 5
python scripts/build.py --range 1-10           # занятия 1–10
python scripts/build.py --all                  # все занятия дисциплины
python scripts/build.py --all --check-only     # только проверки, без записи
python scripts/build.py --lesson 5 --force     # перезаписать без вопроса
python scripts/build_site.py                   # пересобрать сайт
python scripts/build_mobile.py                 # одна страница для телефона
python scripts/preview_deck.py --lesson 5      # картинки слайдов для контроля вёрстки
```

Сайт открывается двойным кликом по `site/index.html`, интернет не нужен.

`build_mobile.py` собирает `site/mobile.html` — один самодостаточный файл,
внутри которого весь текст техкарт и слайды презентаций в виде картинок.
Его удобно открыть с телефона или переслать одним файлом. Скачивание
.docx и .pptx с этой страницы не предусмотрено: она для чтения и вычитки.

### Перезапись файлов

Если файл комплекта уже существует, `build.py` спрашивает подтверждение
(вы могли поправить файл вручную). Ответы: `д` — перезаписать, `н` —
пропустить, `в` — перезаписать все, `п` — пропустить все.
Флаг `--force` перезаписывает без вопросов. При запуске не из терминала
существующие файлы просто пропускаются с предупреждением.

## Проверки перед сборкой

`build.py` не создаёт файлы, пока не пройдут проверки, а расхождения
печатает таблицей:

1. сумма часов по занятиям равна заявленной по каждому семестру и всего;
2. число занятий и сплошная нумерация без пропусков;
3. темы, часы, семестр, раздел, теоретический блок и задание совпадают
   с `docs/plan.md` — план является источником истины;
4. конфиги занятий заполнены: цели, тип, оснащение, ход занятия,
   домашнее задание; сумма минут по этапам равна `45 × часы`;
5. коды ОК/ПК есть в реестре `data/competencies.yaml`;
6. презентация: 12–16 слайдов, не более 5 буллетов и 10 слов в буллете,
   есть слайды темы и цели, вопроса, закрепления, итога и домашнего
   задания, не менее двух слайдов разобранного примера, содержимое
   слайда-примера физически помещается на слайд;
7. практическая часть: критерии оценки и эталон решения (для теста —
   10 вопросов: 8 закрытых и 2 открытых, у всех есть ключи);
8. после записи — комплектность файлов занятия.

## Структура проекта

```
docs/
  plan.md              тематический план — источник истины по темам и часам
  research.md          исследование: ФГОС, ОК/ПК, формулы, источники
data/
  competencies.yaml    реестр ОК/ПК с отметкой, проверена ли формулировка
  theme.yaml           единое оформление курса (палитра, шрифты, размеры)
  disciplines/
    mdk-04-02.yaml     паспорт дисциплины и сводка 43 занятий
  lessons/
    mdk-04-02/NN.yaml  содержание занятия: цели, ход, слайды, практика
templates/
  base_deck.pptx       база презентаций (создаётся make_templates.py)
  base_doc.docx        база документов со стилями
scripts/
  build.py             сборка комплектов занятий
  build_site.py        сборка сайта
  build_mobile.py      одна страница со слайдами картинками (для телефона)
  make_templates.py    создание шаблонов
  preview_deck.py      служебный просмотр вёрстки слайдов
  lib/                 загрузка конфигов, проверки, генераторы
output/
  ДЛ-301-2024/МДК.04.02/Занятие_NN/    готовые файлы комплектов
  _отчёты/                             отчёт о непроставленных ОК/ПК
site/                  локальный сайт (пересобирается целиком)
  mobile.html          одна страница для телефона
```

Генераторы занятий и сайта пишут **только** в `output/` и `site/`.
В `templates/` пишет один скрипт — `make_templates.py`.
HTML в `site/` вручную не правится: папка пересобирается целиком.

## Как устроен конфиг занятия

Файл `data/lessons/<дисциплина>/NN.yaml` содержит:

- `lesson_type`, `lesson_form`, `methods` — тип и организация занятия;
- `goals` — обучающая, развивающая, воспитательная цели;
- `results` — что знать и уметь после занятия;
- `competencies` — списки кодов `pk` и `ok` из реестра;
- `equipment` — оснащение;
- `keywords` — ключевые понятия (используются поиском на сайте);
- `stages` — ход занятия: `block` (`org`/`theory`/`practice`/`final`),
  `stage`, `time`, `minutes`, `teacher`, `student`;
- `homework`, `literature`, `teacher_notes`;
- `slides` — слайды презентации;
- `practice` — практическая часть (`kind`: `task`, `case` или `test`);
- `slide_count_override` — свой лимит числа слайдов (для занятий на 1 ак. ч).

Типы слайдов: `title`, `question`, `bullets`, `definition`, `formula`,
`table`, `two_col`, `scheme`, `example`, `check`, `summary`, `homework`.

## Добавить новую дисциплину

1. Положить тематический план в `docs/plan-<id>.md`.
2. Создать `data/disciplines/<id>.yaml` по образцу `mdk-04-02.yaml`,
   указав в `plan_file` путь к своему плану и перенеся в `lessons`
   сводку занятий.
3. Создать конфиги занятий в `data/lessons/<id>/NN.yaml`.
4. Собрать: `python scripts/build.py --discipline <id> --all`,
   затем `python scripts/build_site.py`.

Реестр компетенций, оформление, генераторы и проверки — общие, править
их не нужно. Файлы каждой дисциплины складываются в
`output/<группа>/<код МДК>/`, на сайте появляется отдельная карточка.

## Правила по содержанию

- Всё на русском, формулировки в стиле документов СПО.
- Числа в задачах учебные; в каждом документе стоит помета
  «Данные условные, используются в учебных целях».
- Реальные компании, статистика, статьи законов и ГОСТы не используются.
- Коды ОК/ПК берутся только из `data/competencies.yaml`. Если формулировка
  подтверждена лишь частично, в документ добавляется пометка
  «сверить формулировку с РП»; если код не найден — печатается
  `[ОК-?]` / `[ПК-?]`, и место попадает в отчёт
  `output/_отчёты/<МДК>_непроставленные_компетенции.md`.
